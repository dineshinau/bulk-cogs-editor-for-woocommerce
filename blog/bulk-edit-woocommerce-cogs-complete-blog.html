Need to bulk edit WooCommerce COGS after a supplier changes prices? With Bulk COGS Editor for WooCommerce, you can filter products, preview new costs, choose which products to update, and apply the changes in background batches.

You can also import different costs for individual products from CSV or Excel, export current costs to CSV, and review previous operations in History. When original cost records are still available, rollback lets you review and restore eligible changes.

This guide covers the complete workflow in version 1.2.0, including CSV/XLSX import, CSV export, History, rollback, and Settings. The plugin works with WooCommerce’s native Cost of Goods Sold feature and changes product costs without changing regular or sale prices.

What is Bulk COGS Editor for WooCommerce?

Bulk COGS Editor is a free, open-source WordPress plugin for managing WooCommerce’s native product cost values. It helps you apply one cost adjustment to a group of products or bring individual costs into your store from a spreadsheet.

For example, if a supplier raises costs by 5%, you can filter the affected products and preview a 5% increase. If the supplier sends a file containing different new costs for each SKU, use CSV or Excel import instead.

Before you start

Your store needs WordPress 6.7 or later, WooCommerce 10.3 or later, and PHP 7.4 or later. Enable WooCommerce’s native Cost of Goods Sold feature in WooCommerce settings before using the editor.

To install the plugin, go to Plugins → Add New Plugin, search for Bulk COGS Editor for WooCommerce, and install and activate it. Then open Products → Bulk COGS Editor. If native COGS is unavailable or disabled, the editor explains what is required.

Before a major production update, take a current backup and check a small product group first. A preview helps you verify the intended changes, and a backup provides a separate recovery option.

How to bulk edit WooCommerce COGS

1. Find the products you want to update

Open the Bulk edit tab. Search by product name or SKU, or narrow the results using product categories and product types. Open More filters for additional options such as stock status, brand when available, current price, and current COGS.

Combine filters to target a particular group, then click Find products. The matching total includes a separate breakdown of products and variations.

Selecting a parent category also matches products in its child categories. Variations use their parent product’s categories. Leave a filter empty when you do not want it to restrict the results.

2. Choose a cost action

Use the Update action control to set an exact cost, adjust an existing cost, or clear it. For adjustments, choose the direction and whether to use a percentage or fixed amount.

Percentage and fixed-amount adjustments skip products without a saved cost. Use an exact cost to assign their initial values. WooCommerce treats a zero COGS value as empty; use the clear action when you want to remove a stored value.

3. Preview the changes and choose products

The preview shows current COGS, proposed COGS, and the difference. Increases appear in green and decreases in red. Check several rows before continuing, especially when working with products that have different starting costs.

Select individual rows, select the current page, or select all matching products. You can also clear the selection or use Select a range. The selection summary shows how many products are selected across all pages.

Use Manage columns to show or hide preview fields. This changes the information displayed in the table, without changing product data.

4. Review, confirm, and follow progress

Check the selected count in the action summary and add an optional note, such as “October supplier increase.” Click the review button, inspect the proposed operation, and confirm it to start the update.

Finding products and preparing a preview do not modify costs. Values shown on reviewed pages are checked again before starting and before each update. Changed reviewed products require a fresh preview and confirmation.

Confirmed updates run in background batches using WooCommerce’s Action Scheduler. You can close the browser and return later to check progress. Review the updated, skipped, and failed counts when processing finishes, and expand Recent activity → View details to inspect the latest result.

Example: increase supplier costs by 5%

Suppose a supplier increases costs across one product category. Open Bulk edit, select that category, and click Find products. Choose Adjust existing cost → Increase → Percentage and enter 5.

A product with a current cost of ₹200 should show a proposed cost of ₹210. Review the matches, exclude products that should keep their current cost, and confirm the update. For other amounts, calculated results follow the store’s decimal precision.

How to export WooCommerce product costs to CSV

Export current costs when you want to review them in a spreadsheet or prepare different new costs for individual products.

  1. Open CSV import / export and choose Export CSV.
  2. Choose the output columns. Keep a product ID or SKU if you plan to import updated costs.
  3. Filter your products, click Find products, and review the selected results.
  4. Click Create CSV and download the file when ready. Keep the page open until the download is ready.

The exported file includes a blank new_cogs column. Fill it with the costs you want to apply, keeping the product identifiers unchanged, then import the edited file.

You can open the CSV in Excel. Export uses CSV format, even if an earlier import used XLSX. Creating an export does not change product costs.

How to import WooCommerce COGS from CSV or Excel

Use import when different products need different new costs. The plugin accepts UTF-8 CSV and Excel XLSX files, identifying products by ID or SKU.

1. Prepare your cost spreadsheet

In CSV import / export, choose Import CSV and click Download template. Despite the option’s name, you can upload either CSV or XLSX.

Your file needs new_cogs and either id or sku. For example:

id,sku,new_cogs
123,PRODUCT-001,25.50
124,PRODUCT-002,40.00

Replace the example IDs and SKUs with products from your store. If both identifiers are provided, they must refer to the same product.

  • Use decimal costs without currency symbols.
  • Leave a cost blank to skip that row. A blank value does not clear an existing cost.
  • Avoid duplicate product rows. Duplicates are excluded and listed in the error report.
  • For XLSX, use the first worksheet and replace formulas with values.
  • Store SKUs as text to preserve leading zeros.

XLSX import requires PHP’s ZIP, XMLReader, and DOM extensions. The upload limit shown beside the file field comes from your WordPress configuration. The limit in the example screenshot belongs to that test site; your store may show a different value.

2. Upload and validate the file

Choose your CSV or XLSX file and click Validate file. The plugin prepares a preview in background batches without changing product costs. You can leave the page and return to check preparation progress.

3. Review the import and confirm the update

When preparation finishes, inspect the matched products and proposed costs. Download validation errors where available, correct affected rows, and validate the revised file if needed.

Select the products to update, review the changes, and confirm the operation. Then follow the background update and check its final results. Preview preparation and the applied update have separate cancellation controls.

Prepared import previews and reports normally expire after about 24 hours, with retention extended while an applied update is active. If your preview expires, upload and validate the file again.

Review previous COGS updates in History

The History tab helps you find previous operations and inspect their recorded results. Filter by status, operation type, user, or date range, or search by operation ID, note, or product ID.

Click View details to inspect an operation’s status, timing, and outcomes. Where original cost records are retained, you can also inspect recorded product changes and check rollback availability.

How to roll back WooCommerce COGS changes

If you applied an incorrect cost update, review a rollback to restore eligible products to their recorded original costs.

  1. Open History and find the operation.
  2. Click View details, then Review rollback when available.
  3. Compare current and original costs and check the rollback policy.
  4. Choose Confirm rollback and monitor the results.

Rollback requires retained original values. Expired operations and older summary-only records cannot be rolled back. If the option is unavailable, check the operation’s details rather than assuming every history entry can be reversed.

If a rollback is cancelled or does not finish, review a new attempt for the remaining products. Already restored products are excluded, even if their costs have been edited again later.

Configure history retention and rollback in Settings

The Settings tab controls how long operation records and original costs remain available, and how new rollbacks handle subsequent cost edits.

History retention

Choose 30 days, 90 days, or a custom period from 1 to 36,500 days. The default is 30 days. Pick a period that gives your team enough time to review completed cost updates.

Shortening retention also affects existing history. Increasing it cannot recover original costs already removed by scheduled cleanup.

Rollback behavior

Suppose an operation changed a product’s cost from ₹100 to ₹110, and someone later edited it to ₹120. Your chosen rollback policy determines how that later edit is handled:

  • Overwrite current costs with original costs: restore the recorded ₹100 cost.
  • Skip changed products: preserve the later ₹120 edit by skipping that product.

Click Save settings after choosing your policy. The behavior shown during rollback review stays fixed for that attempt.

What happens if you cancel a cost update?

Click Cancel operation to request that processing stop. A batch may already be running, so a few more products can finish before cancellation takes effect.

Cancellation keeps costs already saved. For example, if 150 products were updated before the operation stopped, those changes remain. Restoring them requires a separate rollback from History while their original values are retained.

Working with variations and large catalogs

Variations are treated as individual product records with their own COGS values. When you select only variations, their variable parent products are not changed.

For large catalogs, updates run in batches and record progress and product outcomes to support recovery after interruptions. Processing time depends on hosting resources, database speed, product types, installed extensions, and background worker availability.

You do not need to keep the browser open for import preview preparation or confirmed updates. Background workers still need to run on your site. If progress stops, check your site’s scheduled-task setup or ask your host to investigate. CSV export is different: keep its page open until the download is ready.

Frequently asked questions

Does Bulk COGS Editor change selling prices?

No. It updates WooCommerce’s native Cost of Goods Sold values. Regular prices and sale prices remain unchanged.

Should I use bulk edit or CSV import?

Use bulk edit when one adjustment applies to a group, such as increasing costs by 5%. Use CSV or XLSX import when individual products need different new costs.

Can I export WooCommerce COGS as an Excel file?

The plugin exports CSV files, which you can open in Excel. It accepts XLSX imports but does not produce XLSX exports.

Does uploading a spreadsheet immediately change costs?

No. Uploading and validating a file prepares a preview. Product costs change only after you review and confirm the update.

Is there a fixed import row limit?

The plugin has no separate file-size or row-count limit. WordPress’s maximum upload size and your hosting’s memory, storage, and execution limits still apply. Test a representative file before planning a large import.

Can I undo every previous update?

No. Rollback is available for eligible changes with retained original costs. Expired records and older operations containing only summary results cannot be restored through rollback.

Does the plugin send store data to an external service?

No. The plugin performs its COGS calculations and updates locally on your WordPress/WooCommerce installation and does not send product, customer, order, or store data to external processing services.
