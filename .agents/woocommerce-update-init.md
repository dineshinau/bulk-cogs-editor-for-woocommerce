## STEP 1 — Deep Project Analysis

Perform a thorough scan of the entire project tree. Specifically:

1. **Read the main plugin file** (`*.php` at root with `Plugin Name:` header) — extract:
   - Plugin Name, Version, Requires WP, Requires PHP, Text Domain, Domain Path
   - Main class instantiation pattern

2. **Map the directory structure** — identify:
   - `assets/`, `helper/`, `includes/`, `languages/`, `templates/`, `woocommerce/`
   - Any sub-plugins or bundled libraries under `modules/`
   - `composer.json` / `package.json` — note versions

3. **Catalogue all public hooks** — scan for `do_action()` and `apply_filters()` calls. Note their names and arguments.

4. **List all REST API endpoints** — scan for `register_rest_route()`.

5. **List all AJAX handlers** — scan for `wp_ajax_` and `wp_ajax_nopriv_` hooks.

6. **Identify database operations** — custom tables (`dbDelta`), custom meta keys, transient keys.

7. **Detect update/migration logic** — look for version comparison checks, `update_option( 'plugin_version' )`, upgrade routines.

8. **Check test coverage** — scan `tests/` for PHPUnit, Playwright, or Jest tests. Note what's covered.

9. **Find TODO/FIXME/HACK comments** in PHP, JS, and CSS files.

10. **Run PHPCS** (if vendor exists):
    ```bash
    ./vendor/bin/phpcs --standard=phpcs.xml --report=summary . 2>&1 | head -60
    ```

## STEP 4 — Initialize `CLAUDE.md` (Memory)

Create `CLAUDE.md` — this is the persistent memory file Claude CLI reads automatically on every session:

```markdown
# Project Memory — {Plugin Name}
<!-- Claude CLI persistent context — keep this file accurate and current -->
<!-- lwdt: {YYYYMMDDHHII} -->

## Identity
- **Plugin:** {Plugin Name} `{slug}`
- **Version:** `{x.y.z}` (update this on every release)
- **Stack:** PHP {min}+, WordPress {min}+, WooCommerce {min}+
- **Repo root:** `./`
- **Main file:** `./{slug}.php`

## Coding Rules (non-negotiable)
1. All PHP must pass `./vendor/bin/phpcs --standard=phpcs.xml` with **0 errors**.
2. Run `phpcbf` before presenting any PHP code.
3. Prefixes: `wk_`, `wk_marketplace`, `wkpu_`, `wk_caching` — use consistently.
4. Text domains: `wk-marketplace`, `wkpu_updates`, `wk_caching`.
5. PHP 7.4 minimum — no PHP 8.0+ syntax without compat shim.
6. Yoda conditions, tabs (width 4), spaces inside `( )`.
7. Always `wp_unslash()` + sanitize `$_POST`/`$_GET`. Always `esc_*()` on output.
8. `$wpdb->prepare()` for every query with dynamic data.
9. Verify nonce before processing any form or AJAX request.
10. No `eval`, `goto`, `@` suppression, short open tags, or debug output in committed code.

## Key Paths
| Path | Purpose |
|---|---|
| `includes/` | Core classes |
| `admin/` | WP-Admin screens |
| `helper/` | Front-end logic |
| `templates/` | Overridable templates |
| `modules/` | Bundled sub-plugins |
| `src/` | PHPUnit + Playwright tests |
| `assets/` | JS / CSS (excluded from PHPCS) |

## Active Hooks (summary)
<!-- Keep this updated as hooks are added/removed -->
- See `.agents/features.md` for full hook registry.

## Current Update Cycle
- **Plan:** `.agents/plans/plan.md`
- **Target version:** `{x.y.z+1}`
- **Status:** {Planning | In Progress | Review | Done}

## Decisions & Context
<!-- Append decisions here so future sessions have context -->
- {YYYY-MM-DD}: {Decision made and why}

## Do NOT
- Do not modify files under `vendor/`, `node_modules/`, `build/`.
- Do not commit debug output (`var_dump`, `print_r`, `error_log` with secrets).
- Do not introduce PHP 8.0+ syntax.
- Do not rename existing public hooks without a deprecation notice.
```
