# CSV import and export on the existing editor

Source: https://chatgpt.com/share/6ad62a9e-2028-83e8-8ae6-6aa42e460a5f

## Acceptance criteria

- Keep one admin page, with bulk edit and CSV modes sharing review, selection, pagination and import progress.
- Export all filtered results in bounded read-only requests, with selectable columns and explicit product types.
- Accept UTF-8 CSV up to 1 MB and 1,000 data rows. Match ID first; when both identifiers exist they must agree. Reject duplicate targets, invalid amounts and ambiguous SKUs. Blank costs are skipped, never cleared.
- Preview never writes product data. Only an explicitly confirmed import can create a background operation. Preserve worker locks, durable outcomes, cancellation and retry protection.
- Provide a template and validation error report. Preserve existing bulk edit behavior.

## Implementation

1. Add a CSV parsing/formatting service and authorized AJAX entry points in the existing admin controller.
2. Store validated per-product import values with the existing preview and operation. Reuse the existing worker and selection path.
3. Add mode controls in the existing page and adapt shared preview/pagination. Download export batches as one CSV in the browser.
4. Run PHP formatting, syntax and PHPCS checks, build assets, review the diff and refresh Graphify. No tests or product updates are authorized by this task.

Large-file background parsing and durable export jobs remain phase two, as proposed in the shared chat. Initial exports require the page to stay open; imports continue through Action Scheduler after confirmation.
