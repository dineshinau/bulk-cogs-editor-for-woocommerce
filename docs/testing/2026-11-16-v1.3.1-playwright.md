## Finding and follow-up fix

Initial verification found that when native COGS is disabled, the notice correctly offers the enable action and the server rejects product searches with HTTP 400. However, Find products remains enabled after initialization. `updateOperationControls()` assigns `getButton.disabled = state.busy || running` at `src/bulk-cogs-editor.js:1552`, omitting COGS availability. The button should stay disabled until the feature is enabled. This is a UI issue; the server-side guard prevents updates.

The follow-up fix includes COGS availability in the button disabled state and the product-search handler guard. The suite retains the regression check. The original browser failure above predates this fix; the follow-up build passed.

## Execution notes

Twelve feature checks passed across the full rerun (11 passes) and a targeted enable-button rerun (one pass). A thirteenth check records the disabled-search UI regression described above. The enable-button test initially attempted to read a response body after automatic navigation; its corrected assertion checks the response status and reloaded editor state. Early attempts also exposed test selector, loading-state, fixture-helper, and localized-value assumptions; these were corrected in the suite.

The machine's DNS delayed fixture creation. Temporary WP-CLI wrappers mapped local HTTP requests to localhost and blocked unrelated external HTTP during fixture commands. `DKBCE_E2E_HOST_RESOLVER_RULES='MAP wsl.com 127.0.0.1'` supplied the corresponding Chrome mapping. No global DNS configuration was changed.

Products, users, and operations were disposable fixtures. The health notice cache and COGS feature option were restored after their checks. The suite did not update existing catalog products or install another WooCommerce version. The unsupported-WooCommerce upgrade branch was not exercised.

## Reproduce

```bash
DKBCE_BASE_URL=https://wsl.com/wpdev \
DKBCE_WP_PATH=/var/www/html/wpdev \
DKBCE_E2E_HOST_RESOLVER_RULES='MAP wsl.com 127.0.0.1' \
npm run test:e2e -- tests/e2e/v1.3.1.spec.cjs
```

Local WP-CLI DNS resolution must also work. This session used a temporary wrapper under `/tmp/dkbce-e2e-bin`; it is not a repository dependency.
